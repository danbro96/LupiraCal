# LupiraCal — agent notes

- BFF pattern: ~/Nextcloud/Familj/DevOps/Guides/bff-pattern.md
- Shared frontend conventions: ~/Nextcloud/Familj/DevOps/Guides/frontend-estate.md (repo-specific deviations below).
- **Purpose**: web + mobile UI over LupiraCalApi's REST surface (no sync-protocol paths on web). Visualizes the temporal backbone: calendar Class/Kind, ItemKind details, Prompt/Action payloads, completeness, availability segments, curation, tags, metadata, relations. The map (maps.lupira.com, LupiraMaps) and photo library (photos.lupira.com, LupiraPhotos) are separate apps, as are GPS ingest and camera-roll backup; Cal keeps the event photo strip and the place-tile mini-map and links out (`config/siblings.ts` on web, `ui/openSibling` on mobile, both over `@danbro96/lupira-domain-links`). The BFF 301s `/locations`, `/photos` and `/places` to them (`Siblings:Maps` / `Siblings:Photos`) and answers 404 on the retired `/location-api` and `/ingest` prefixes.
- **Workspaces**: `packages/domain` (`@lupira/cal-domain`, pure TS consumed as source, no deps, never imports generated DTO types), `packages/tokens` (`@lupira/cal-tokens`, same purity; consumers re-type records against generated enums as the drift tripwire), `packages/api` (`@lupira/cal-api`), `apps/web`, `apps/mobile` (Expo 57 "Lupira Calendar", package `com.lupira.calendar`, scheme `lupiracalendar`, Authentik client `lupira-cal-mobile`, own orval gen against the BFF prefixes).
- **BFF**: thin composition over LupiraPlatform `Lupira.Bff.{Proxy,OpenApi,Auth}`, `Lupira.Depz(.Yarp)`, `Lupira.Hosting.*` (`~/Nextcloud/Familj/DevOps/Guides/platform-packages.md`). Authentik client `lupira-cal`, cookie `__Host-lupira-cal`. YARP → six upstream roots (cal, contact, geo, tasks, photo, comms; prefix stripped, bearer attached). No anonymous surface. CalApi Development accepts the forwarded `X-Dev-User`.
- **`/depz`** (BFF's own, not proxied): non-gating availability report, one anonymous `readyz` probe per `ReverseProxy:Clusters` entry named by registry service (`Lupira.Depz.Yarp` service-name map in `Program.cs`); `X-Probe-Key` = `Depz:ProbeKey`, blank = off.
- **`exposed.json`** declares each cluster's `prefix` (routes, 404 fence and 401-on-API prefixes all derive from it). Exception to "no catch-all": group `static` (geo-api `/basemap`, GET-only file subtree; glyph ranges can't be enumerated).
  - Unreachable: `/mcp`, `/internal/*`, `/dav-backend/*`, `/depz`, `/openapi/v1.json`, `/scalar`, `/pingz`, comms `/ingest`, tasks `/shared/{token}` and `/users/directory`.
- **Contract**: six upstream specs merged (cluster tag per upstream). Kiota client so far: `Upstream/Contact` (`GET /api/contacts/{id}/context`). Refresh: copy the upstream spec into `src/LupiraCalBff/upstream/`, then `dotnet tool run kiota update -o src/LupiraCalBff/Upstream/Contact`.
- **API client** (`packages/api`): `query/*` for reads straight off the server, `fetch/*` for callers that own their caching. Every `/me` is dropped but contact's (carries `contactId`); the BFF owns identity at `/auth/user`. Numerics generate as plain `number` (`NumberHandling.Strict`) — never re-add `Number()` coercion.
- **Layering**: `data → state → ui` (+ leaf `config/`) on web, `domain → data → sync → state → ui` on mobile, eslint-plugin-boundaries v7; `@danbro96/lupira-*` imports are allowed per layer (tokens/domain everywhere, http from data up, web/expo kits from ui, their data/feedback/log subpaths from data up). Rules several Lupira apps share live in the `@danbro96/lupira-domain-*` / `-tokens-*` packages (time, wording, item labels, contact names, residents, places + ranking, basemap style, map zoom, photo windows/links, core palette, SCRIM, calendar kinds, map theme, LWW/replay/backoff). `@lupira/cal-domain` holds the Cal-only rules: grid math, occurrence column layout, recurrence prose, partial dates, task-deadline rules, the event form (`itemForm`), calendar choice, `participation`, `photoFormat`; `@lupira/cal-tokens` the Cal-only visual values (palette extras, EMPHASIS, `rsvpTone`). An app keeps only its adapters and widgets.
- **Shared vs per-app.** A hook's query key, gating and return shape stay per-app; the apps share rules through the `@danbro96/lupira-*` packages, not hooks.
- **Mobile keeps hand-written hooks over the generated *fetchers* — do not swap in the generated *hooks*.** Mobile's query keys are the sync engine's invalidation contract: `sync/reactivity.ts` invalidates by domain aggregate (`['photos']`, `['contacts']`, `['items']`, `['occurrences', monthKey]`), react-query matches by prefix, and every hook nests under its aggregate, including cross-API ones (`['photos','event-links']` is a cal-api relations call filed under photos). Route-keyed hooks would silently stop matching. The mobile `QueryClient` defaults to `staleTime: Infinity, retry: false` for the local mirror; generated hooks would fetch once, forever. The web has no sync engine, which is why generated hooks fit there.
- Dev ports: API 5255, BFF 5181, Vite 5174. Prod: cal.lupira.com:40881, image `danbro96/lupira-cal-web`.
