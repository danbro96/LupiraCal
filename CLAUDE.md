# LupiraCal — agent notes

- **Purpose**: web UI over LupiraCalApi's REST surface (REST only, no sync-protocol paths). Visualizes the temporal backbone: calendar Class/Kind, ItemKind details, Prompt/Action payloads, completeness, availability segments, curation, tags, metadata, relations.
- **Monorepo (npm workspaces)**: root `package.json` hoists the toolchain; workspaces = `packages/domain` (`@lupira/cal-domain` — shared pure TS, consumed as source, no deps, never import generated DTO types there), `packages/tokens` (`@lupira/cal-tokens` — design tokens: light/dark `ColorScheme`, semantic palettes, the map layer palette (`map`), spacing/typography/breakpoint; same purity rules; consumers re-type records against generated enums as the drift tripwire; new workspaces must also be added to the Dockerfile's COPY + `npm ci -w` lines), `apps/web`, and `apps/mobile` (Expo 57 "Lupira Calendar", package `com.lupira.calendar`, scheme `lupiracalendar`; layering `domain→data→sync→state→ui`, own orval gen against the BFF prefixes, Authentik client `lupira-cal-mobile`; program tracker in `docs/mobile/milestones.md`). Root scripts fan out (`npm run lint|typecheck|test`) or delegate (`dev|build|gen:api`).
- **Shape**: .NET 10 BFF (`src/LupiraCalBff`) + Vite/React 19 + MUI SPA (`apps/web`) in one image. BFF owns Authentik OIDC (`lupira-cal` client, PKCE, no secret), cookie `__Host-lupira-cal`, Duende token refresh, YARP → the seven upstream roots (prefix stripped, bearer attached). No anonymous surface. Dev: auto-auth + `X-Dev-User` forwarded (CalApi Development accepts it).
- **`/depz`** (BFF's own, not proxied): non-gating availability report, one anonymous `readyz` probe per `ReverseProxy:Clusters` entry named by registry service (`Dependencies/DependencyTargets`); `X-Probe-Key` = `Depz:ProbeKey`, blank = off.
- **The proxy is an allowlist.** `src/LupiraCalBff/exposed.json` names every `VERB /path` the BFF forwards; `Proxy/ProxyRoutes` builds `ReverseProxy:Routes` from it at startup as a config source (one exact template per path, `Match.Methods` pinned) — `dotnet run --project src/LupiraCalBff -- --routes` prints the table, and `UpstreamSpecMerger` filters the published document by the same file — so the proxy and the client cannot disagree, so neither can be hand-edited. Clusters stay in appsettings; a config source is what lets `LoadFromConfig` and the `ApiPrefixes` fence read the routes unchanged. It lists only what the clients actually call; an operation with no caller is not exposed. Adding an endpoint = a line in `exposed.json`; the merge prints anything upstream that isn't listed, and throws if a listed one no longer exists. **Never widen a route to `{**catch-all}`** — that forwards whatever the upstream adds under it, unreviewed. Two exceptions: `exposed.static` (geo-api `/basemap`, GET-only file subtree — glyph ranges can't be enumerated) and `exposed.device` (location-api `/ingest/location*`, mounted at the upstream path with no transform, `AuthorizationPolicy: Anonymous`). **Ingest is Anonymous because only location-api holds the device keys** — the BFF gates on `DeviceKey {32hex}.{64hex}` well-formedness (`Auth/DeviceKeyHeader`, 401 before the proxy so a device never gets an OIDC redirect) and the YARP transform stands aside so the header reaches the upstream untouched. It stays out of the merged spec: the generated client can only express Bearer, which is why the uploader is hand-written. **Web and both mobile apps talk only to the BFF** — no client may call an upstream origin. Deliberately unreachable: `/mcp` (proxying it tunnels past the Cloudflare edge exclusion), `/internal/*`, `/dav-backend/*`, `/depz`, `/openapi/v1.json`, `/scalar`, `/pingz`, comms `/ingest`, tasks `/shared/{token}` and `/users/directory` — the ingest and share-link surfaces authenticate with a device key, service credential or bearer token, not the family session. An API path matching no route 404s (`ApiPrefixes` fence in `Program.cs`); without it the SPA fallback answers 200/HTML and a dead route looks alive.
- **The BFF owns its own contract.** `src/LupiraCalBff/OpenApi/UpstreamSpecMerger` reconstructs the BFF's OpenAPI document from the seven upstream specs it proxies (committed + embedded under `src/LupiraCalBff/upstream/`, allowlisted by `src/LupiraCalBff/exposed.json`): prefixes each cluster's paths with its BFF mount, dedupes identical schemas and namespaces the rest. `BffDocumentTransformer` grafts it onto the ASP.NET document, so **every `dotnet build` writes `openapi/LupiraCalBff.json`** — the spec is a build artifact, not something a script manufactures — and the BFF serves `/openapi/v1.json` + `/scalar` (authenticated: the document is the whole internal API map). It merges on the JSON DOM, not `OpenApiDocument`, because renaming a colliding schema means retargeting its `$ref`s and the typed model exposes referenced nodes read-only. **Refreshing an upstream spec**: copy it into `src/LupiraCalBff/upstream/`, then `dotnet run --project src/LupiraCalBff -- --normalize-specs src/LupiraCalBff`, then regenerate any C# client (`dotnet tool run kiota …`, pinned in `.config/dotnet-tools.json`), then build. Two passes because a generated C# client compiles *into* the BFF, so the BFF cannot produce the generator's input in the same build.
- **`upstream-normalized/` is the C# generator's input, not the published contract.** `TODO(kiota)`: the whole pass goes once a kiota release carries [the oneOf-null fix](https://github.com/microsoft/kiota/pull/8064) (merged 2026-08-19, unreleased as of 1.34.1) — the specs are correct, OpenAPI 3.1 has no other way to say "nullable reference". `NullableRefNormalizer` collapses `oneOf: [{type:"null"}, {$ref:X}]` to a bare `$ref` (72 sites) because Kiota models every `oneOf` as a composed type — left alone it emits a wrapper class plus a junk member type per property (39 each in cal) and reads become `item.Status?.ItemStatus`. **Never normalize the published document**: orval uses the null branch and emits `status?: null | ItemStatus`, so collapsing there silently strips the null from the TS types. `normalized-specs.test.ts` pins both halves.
- **The BFF can serve an endpoint itself, and that is how one leaves the proxy.** `Endpoints/` declares the route, `Handlers/` holds the logic, `Dtos/` the response shape, and `Upstream/<Cluster>/` a Kiota client generated from `upstream-normalized/` (scoped with `--include-path`, so only the operations a handler calls are generated). **`SessionTokenHandler` is what makes this work** — the YARP transform only runs on proxy routes, so without it a handler calls upstream unauthenticated; it mirrors the transform exactly (caller's own Bearer forwarded, `X-Dev-User` in dev, otherwise the session's access token) and Kiota is deliberately given an `AnonymousAuthenticationProvider` so there is one auth path, not two. Base addresses come from `ReverseProxy:Clusters`. **Kiota throws on non-2xx where the proxy passed the status through**, so a handler must map 404/403 itself or an upstream 404 reaches the SPA as a 500. Migrating an endpoint = declare it, drop its `exposed.json` line, and **extend the matching `useInvalidate` predicate** — a BFF path does not share the upstream prefix, so a mutation would otherwise leave it stale. First one: `GET /api/contacts/{id}/context` — the contact pane's groups (every readable book's, since membership is cross-book; joinable = writable books only, via contact-api `/sync/containers`) and emergency-contact names in one call.
- **API client is generated, once, in `packages/api`** (`@lupira/cal-api`), from `openapi/LupiraCalBff.json`. That is what makes query keys collision-free: orval derives them from the path, and `/pingz` lived in four specs, `/items` in two. **Never hand-prefix a query key again.** Both flavours are generated over one set of models — `query/*` (react-query) for anything read straight off the server, `fetch/*` for callers that own their caching. Each app installs its own `setApiTransport` (`packages/api/src/transport.ts`); paths already carry their prefix, so no mutator prepends anything. Refresh with `npm run gen:api` (→ `npm run gen -w packages/api`) after any upstream endpoint change; never hand-edit `packages/api/src/generated/`. orval's `clean` is off, so a schema that leaves the spec lingers as an orphan model — when one does, `rm -rf packages/api/src/generated/models` before regenerating. Every `/me` is dropped but contact's, which alone carries `contactId` — the BFF owns identity at `/auth/user`. Numerics generate as plain `number` (the APIs set `NumberHandling.Strict`) — never re-add `Number()` coercion at use sites.
- **UI stack (web)**: MUI v9 (Emotion; per-component default imports; v9 API only — `slots`/`slotProps`, `sx`). Theme = `ui/theme/muiTheme.ts`: `createTheme({cssVariables: {colorSchemeSelector: 'media'}, colorSchemes})` fed from tokens (teal primary), system-driven dark, breakpoint `md: 821` = the phone breakpoint (`useIsPhone` wraps `useMediaQuery`). **Every token comes from the theme**: palette (incl. custom `border` + `text.subtle` + `warning`/`success`) emits `--mui-palette-*`; the domain relation accents emit as `--cat-*` via `MuiCssBaseline` styleOverrides, sourced from `@lupira/cal-tokens/contactCategories`. **Styling lives in the theme, then `sx` — there is no bespoke stylesheet.** `index.css` is 39 lines: Tailwind's two entry points, an `@theme inline` that re-exports `--cat-*` as `cat-*` utilities, three element resets, and `.map-canvas` (maplibre-gl.css forces `position:relative` on its own wrapper, so the host must size as a flex child). Tailwind 4 is present for utilities on non-MUI elements and for vendor DOM you can only reach with an arbitrary variant. **Never set `modularCssLayers`** — MUI 9.3.1 declares `mui.*` layers it never emits, so the declared order governs nothing and `sx` silently loses to component styles. Emotion stays unlayered and outranks Tailwind, which is safe only because no element carries both. **Two `className` hooks are deliberate and load-bearing**: `.contact-row` (so the pin reveals on row hover) and `.map-canvas`. **MUI v9 narrowed system props** — `Stack` takes only `direction`/`spacing`/`divider`/`useFlexGap`/`sx`, and `Typography` ignores `color` for palette paths; put both in `sx`, and use `useFlexGap` on any wrapping `Stack`. Vendor stylesheets (maplibre, xyflow) are unlayered and so outrank every layer: overriding their own rules needs `!`. Shared layout primitives live in `ui/components/`: `WrapRow`, `DrawerSection`, `Page`/`PageHead`, `Row`/`RowName`, `panes.tsx`. Forms = react-hook-form (`Controller`-wrapped MUI fields; ContactEditForm gates its 8-endpoint fan-out by payload comparison, not dirtyFields). Mutation errors → `useSnackbar()` (SnackbarHost); field validation stays inline. Detail cards share `drawer/DetailDrawer.tsx`. A place renders as `places/PlaceTile` (name, one-line address, meta, a lazy `map/MiniMap` thumbnail framed by `@lupira/cal-domain/mapZoom`, copy button via `useCopy`); per-browser conveniences (last calendar, calendar view per layout, map layers/range) live in `state/localPrefs`, behind the URL. Build splits a `vendor-mui` chunk (rolldown `advancedChunks`).
- **UI stack (mobile)**: react-native-paper 5 (MD3) themed from tokens via `ui/theme/paperTheme.ts` (+ adapted React Navigation themes); dark mode via `useColorScheme`. The whole palette rides on the Paper theme and **`useColors()` is the app's only colour hook — never Paper's `useTheme()` directly** (same rule as tasks-mobile/assistant-mobile). Two files are the documented exception, each because it needs an MD3 slot the estate palette has no equivalent for: `SyncBanner` (errorContainer) and `MapScreen` (elevation ramp). Confirm flows use `useConfirm()` (ConfirmDialogHost) and transient failures `toast()`/`toastError()` from the `feedback/` leaf (host: `ToastHost`, Paper `Snackbar`); hold-to-copy (place tiles, reach rows) is `copyText()` in the same leaf — same shape as the sibling apps; `useUnsavedGuard` keeps `Alert.alert` (fires inside `beforeRemove`). `Button`/`ConfirmDialog` are byte-identical to the sibling apps' copies. Text inputs use the `Input` wrapper in `ui/components/form.tsx` (Paper `TextInput`, outlined+dense, label prop — `Field` is only for non-text controls), which keeps a column-rhythm `marginTop` where the siblings' `TextField` carries a row-layout `flex: 1`. No hex literals except white text over calendar-colored backgrounds. A place renders as `ui/components/PlaceTile` everywhere (name, address, meta line, `ui/map/MiniMap` thumbnail — a texture-mode, gesture-less `MapView`, so detail screens only, never lists, framed by place type via `@lupira/cal-domain/mapZoom`; tap → Map tab `at`); tags as `TagRow` text, never chips. Detail screens carry no container padding: Paper rows and subheaders bring their own 16dp, other blocks take `spacing.lg`. `debug/log.ts`, `DebugLogScreen` and `DeveloperScreen` are shared with the sibling apps — a redacted zustand buffer plus Sentry breadcrumbs, gated in Settings on the `debugEnabled` pref. Tabs are Calendar/Contacts/Map/Photos, each showing the native header; Settings is a pushed stack screen reached by `SettingsButton` in the tab navigator's `headerRight` — an index whose rows show each area's state (warning colour when it needs you) and open `CalendarSettings`/`PhotoSettings`/`LocationSettings`/`AndroidSettings`. Contacts' search sits in `ScreenToolbar` under that header. Calendar has no toolbar: the header title is the period (tap = date picker) and Search/Today/Month↔Week sit beside the cog (`useCalendarHeader`, via `setOptions`) — the grid needs the rows. `CalendarScreen` owns only anchor and jumps (the Month/Week mode is `prefs.calendarMode`); `MonthPane` (grid + `DaySheet`) and `WeekView` own their paging and selection. Every calendar gesture is RNGH + Reanimated — swipes, the day sheet's drag, and the week's pinch zoom (time axis, persisted as `prefs.weekHourHeight`), with the lanes' ScrollView joined via `Gesture.Native()`; a PanResponder loses that race to the native scroll. Both modes page with `usePager`: prev/current/next stay rendered (21 date-keyed columns / 3 month-keyed grids) on an axis fixed at mount, and a swipe only moves the axis, so the neighbour is live under the finger and a step re-renders nothing visible — never reset the offset on a swipe; a `CalendarJump` (Today, picked date) is the one snap. Lanes are laid out in percent of the day so a zoom frame animates one height. Search (`ItemSearchScreen`) reads the mirror, not the API, so it works offline. Program tracker: `docs/mobile/milestones.md` (M13).
- **Screens** are `ui/screens/XScreen.tsx` with a named export. The three lazy routes (`MapScreen`, `PlacesScreen`, `PhotosScreen`) keep `export default` because `React.lazy` needs one; the filename still matches the symbol. `ContactsLayout` lives in `ui/navigation/` — it is routing structure, not a screen. Mobile's root navigator is `ui/navigation/RootStack.tsx`, as in the sibling apps.

- **Mobile sync** (`sync/pull.ts`): both `/sync/changes` cursors are opaque and scoped to the caller's readable containers — a grant/revoke answers `reset`, which makes the run a full sync. A full sync that never completed restarts (`getResumeCursor`): its prune needs every id. The container pull seeds a missing standard set (`@lupira/cal-domain/bootstrap`, shared with web). Non-network sync failures go to Sentry (`SENTRY_DSN` in `config/`, empty = off; user id = SHA-256 of the email).

- **Mobile keeps hand-written hooks over the generated *fetchers* — do not swap them for the generated *hooks*.** Its query keys are the sync engine's invalidation contract: `sync/reactivity.ts` invalidates by domain aggregate (`['photos']`, `['contacts']`, `['items']`, `['occurrences', monthKey]`), react-query matches by prefix, and every hook nests under the aggregate it belongs to — including cross-API ones, so `['photos','event-links']` is a **cal-api** relations call filed under photos. No route prefix expresses that grouping. Route-keyed hooks would simply stop matching, silently, leaving stale screens. The mobile `QueryClient` also defaults to `staleTime: Infinity, retry: false` for the local mirror, which network-backed hooks each override — generated hooks would inherit it and fetch once, forever. The web has no sync engine and no such contract, which is why the generated hooks fit there and not here.

- **What is shared, and what stays per-app.** Pure logic the two apps agree on lives in `packages/domain` or `packages/tokens`; a hook's query key, gating and return shape stay per-app (mobile's keys are the sync engine's invalidation contract), and so do the MapLibre layer components — same expressions, but per-renderer wrappers and touch-vs-pointer sizes. `useMapData` and `usePhotoLibrary` already delegate to `mapFeatures`/`photoFormat`; what remains in them is DTO-vs-mirror-row adaptation, which is not drift. Shared behaviour both apps render: `participation` (attendee wording), `placeCandidates` (the place picker's ranked list + residents), `quickPlaces` (the map jump strip), `mapHits`/`mapHitLabels` (what a map tap found and says), `mapZoom`, `residents`; `@lupira/cal-tokens/mapLayers` is the one layer list (labels, colours, icon concepts, defaults).

- **Stay in step with the sibling Lupira frontends.** Same components, theme wiring and layout;
  match what they already do rather than inventing a local shape. Shared files stay byte-identical.
- **Topbar**: every root screen shows the navigator's native header — title from `options.title`,
  actions from `headerRight`, and the cog is the shared `SettingsButton`. Never `headerShown: false`
  on a root screen. A screen's own controls (search, period nav, filters) go in `ScreenToolbar`,
  a row *under* the header, not instead of it — except Calendar, whose period controls are the header.
  Status strips render nothing when healthy.
- **Header actions are declared in the navigator's `options`**; `useLayoutEffect` + `setOptions` only
  when the action gates on screen state (a Save enabled only when dirty).

  and for clearable single-select. Each lives only where it is used — copy it across when a second app

- **Layering**: `data → state → ui` (+ leaf `config/`), enforced by eslint-plugin-boundaries v7. Domain logic lives in `@lupira/cal-domain` (pure + vitest-tested: grid math, occurrence column layout, recurrence-rule/fire prose, partial dates, task-deadline rules (`tasks`), basemap style handling (`mapStyle`), place-lookup batching (`places`)), importable from every layer; its purity is enforced by its own eslint config.
- **Calendar visibility + writability** (`@lupira/cal-domain/calendars`): Agenda calendars start shown, System hidden; a per-calendar choice overrides — web `CalendarToggles` (side panel on desktop, sheet on phones; only the calendar screen renders it), remembered in `localPrefs`; mobile Settings → Calendar, `prefs.calendarChoices`, applied by `useCalendarFilter` to the grids, search, map events and the jump strip (Birthdays hides synthesized birthdays). Every filing picker offers only `canWriteCalendar` (Owner/ReadWrite) calendars.
- **Grids are hand-rolled** (no calendar lib): `GET /items?from&to` returns recurrence-expanded occurrences; grids still fan out one query per visible calendar although the occurrence DTO now carries `calendarIds` (single-query refactor pending). Proposed items ghost from `GET /calendars/{id}/proposed`; availability band joins occurrence → item detail for status.
- **Map** (`/locations`, nav label "Map"): lazy route (`React.lazy` — maplibre-gl stays in its own chunk). Data: occurrences+contacts hydrate placeIds via geo `POST /places/lookup` (`usePlaceCoords`, key `/geo-api/places/lookup` — a hand-written query over a POST, which orval generates as a mutation); GPS via `/location-api` prefix (`@lupira/cal-api/query/location`). Basemap = geo-api `/basemap/style.json?theme=` + pmtiles (client rewrites URLs absolute in `mapStyle.ts`; fallback wash when unprovisioned). Layer palette is `@lupira/cal-tokens/map`, dataviz-validated — don't tweak hues casually; Unknown activity = dashed gray, never a fifth hue. MapLibre/React glue is centralized in `useGeoJsonLayer` (re-adds sources/layers on styledata; layers only declare which ids are `interactive`, for the cursor). **Clicks are the screen's, not the layers'**: `MapClicks` queries every interactive layer under the pointer at once → `@lupira/cal-domain/mapHits` → `MapHitsCard` in `MapPopover` (one hit = card, several = list; text and actions from `mapHitLabels`), with a `SelectionMarker` on what was picked — per-layer handlers fired several at once on stacked pins. The range bar (Today … Year/All, default 30 days) bounds every dated layer — events, photos, hotspots, movement (`trackBucketSeconds`); layers (`layers=none` is a choice, not an absence) and the range preset are remembered in `state/localPrefs` for when the URL names none. `?at=` pins at zoom 16, and a deep link (`at`/`place`/`item`) stops `FitToData` pulling the camera away. A jump strip (`useQuickPlaces` → `@lupira/cal-domain/quickPlaces`) lists your home, work and next placed events. **The photo layer is clustered by photo-api, not MapLibre**: `/photos/map` takes the viewport's `zoom` and answers per-cell counts (a feature with `count > 1`, tap = fit `photoCellBounds`) or single photos — client clustering there would re-cluster the cells, and any client-side cap brings back the bug where newer photos crowd older places off the map. **maplibre-gl v6 worker gotcha**: its default worker URL (sibling of the entry module) 404s under bundlers, and bundling the worker yourself (`?worker&url`) emits an EMPTY file in prod (tree-shaken — maplibre's `sideEffects` allowlist; symptom: FF "Attempting to create a Worker from an empty source", gray map, zero `sourcedata`). Fix in place: `sync:maplibre` script vendors `maplibre-gl-worker.mjs` + `maplibre-gl-shared.mjs` verbatim into `public/maplibre/` (gitignored, runs predev/prebuild) + `setWorkerUrl('/maplibre/maplibre-gl-worker.mjs')` in `components/map/maplibreSetup.ts` (a side-effect module every map constructor imports — `MapCanvas`, `MiniMap`) — don't remove either half. A missing basemap *sprite* is equally fatal (style stuck loading); `loadMapStyle` Range-probes the pmtiles and falls back to `fallbackStyle` when assets are unprovisioned. **Mobile Map tab** (`apps/mobile/src/ui/screens/MapScreen.tsx`): `@maplibre/maplibre-react-native` — MapLibre Native reads `pmtiles://https://` sources directly (no worker/protocol shims); the style document handling (absolutize URLs, Range-probe the tiles, fall back) is `@lupira/cal-domain/mapStyle`, and each app's `mapStyle.ts` supplies only its transport — cookie on web, bearer on mobile; bearer for native tile/glyph/sprite requests rides `TransformRequestManager.addHeader` with a stable id (in-place token rotation) and a `match` scoped to the BFF origin — never let that header reach presigned or third-party URLs. Layers split into `apps/mobile/src/ui/map/layers.tsx`; chrome (layers sheet + locate FAB) in `MapChrome.tsx`. Taps are the map's, not the sources': `queryRenderedFeatures` per layer under the finger → `@lupira/cal-domain/mapHits` → `MapPreviewSheet` (one hit = card with its Open, several = list); a cluster that can't split past `clusterMaxZoom` lists its leaves. The tapped or handed-over point gets `SelectionPin`. An `at` target waits for `onDidFinishLoadingMap` — the map mounts after its style loads, so an early `easeTo` is silently dropped. One age limit (`prefs.mapSince`, `@lupira/cal-domain/mapWindow`) bounds events, photos, hotspots and movement; layer toggles persist in `prefs.mapLayers`. A jump strip under the header (`QuickPlacesStrip`, `useQuickPlaces`) lists your own contact's current Home/Work addresses, then the next placed events (`upcomingPlacedEvents`); a jump frames by place type (`@lupira/cal-domain/mapZoom`) and an event opens its preview card. **The phone is the estate's only GPS uploader** — `sync/locationRecorder.ts` records under an Android foreground service into `location_fix_queue`, `sync/locationUploader.ts` drains it. Ingest is the one call that does NOT ride the BFF: it authenticates with `Authorization: DeviceKey …`, which the BFF's OIDC-only policy rejects, so it posts straight to `LOCATION_INGEST_URL` and must stay hand-written (the OpenAPI doc declares only a Bearer scheme). NDJSON lines are snake_case and must never carry principal/device ids — the server rejects the whole line. Cadence adapts to speed but **accuracy stays High in every profile**: Balanced is ~100 m, above the server's 50 m cutoff, and still-mode is exactly when visits (80 m / ≥8 min) are detected — a cheap still profile silently yields zero visits. Cadence changes call `startLocationUpdatesAsync` again rather than stop+start (Android 12+ forbids restarting a location FGS from the background). The task is registered in `index.ts`, not from a React effect — a headless restart has no App component.
- **Photos** (web `/photos`, reached from BottomNav's More; mobile Photos tab): day-grouped, cursor-paged grid over `/photo-api/photos` — sort `TakenAtDesc`/`TakenAtAsc` (the cursor encodes its direction and the server rejects a mismatch), filters kind/located/place/status/event, plus `trashed` for the trash view. `GET /photos/stats` feeds the year/month timeline (a pick filters to that span rather than scrolling — an unloaded month would mean paging through everything since) and the failed chip; `POST /photos/lookup` hydrates relation ids in one call. The event filter resolves client-side (edges → lookup → `@lupira/cal-domain/photoFilter`), never by paging the list. Both grids multi-select for bulk link/unlink/trash, and one event picker (`LinkEventDialog` / `LinkEventSheet`, window `captureWindow`) serves a single photo and a selection; links go through `POST /items/{id}/relations/batch[/delete]`, so an Undo is one call. **Delete means trash**: `POST /photos/{id}/trash` offers Undo (restore) instead of a confirm; only "Delete for good" and "Empty trash" confirm, and the server purges after `purgesAt`. Web Undo actions are plain fetchers (`usePhotoActions`), not mutation hooks — the snackbar outlives the component that offered it. Search is one box (web `PhotoSearch`, mobile `PhotoSearchSheet`): dates from the stats timeline (`matchTimeline`), events from cal `searchItems`, places from `GET /photos/places`; free text filters by place. Day headers carry the day's top places and linked events (`topPlaces` / `linkedEventIds`), each a filter. The mobile viewer's Save goes through `saveOriginalToPhone`, which files the copy as already uploaded in `photo_upload_queue` — it is a new MediaStore asset with a fresh creation time, so the next scan would otherwise upload it again. **Presigned URLs rotate their signature**, so mobile image caches key on the asset id via `source.cacheKey` (`ui/photos/imageCache` — `recyclingKey` only resets recycled views, it is not a cache key), photo-api reuses each signed URL for half its life so the browser cache hits too, and `staleTime` stays well inside the 24 h thumb expiry; the newest unfiltered page is kept in `mirror_meta` (`data/photoSnapshot`) so an offline launch still has a grid; `originalUrl` is single-asset-only and short-lived, so the viewer fetches it for the page in view alone. HEIC originals are served untranscoded — neither client can decode them, both fall back to the thumbnail. Photo↔event links are cal-api `Relation`s with `toKind: 'photo'` (`GET /relations/edges?toKind=photo` returns the whole map in one call); candidates come from items around `takenAt` and are always confirmed, never auto-linked — the window is `@lupira/cal-domain/photoWindow` so both clients suggest the same set, and the item drawer/detail screen offers the photos taken while an event was happening. **Duplicates are detected server-side, twice**: a surrogate `(takenAt, sizeBytes, contentType)` match at declare returns `Status: Duplicate` with no upload URL (so a second phone never transfers the bytes), and the worker hashes the original it already streams for the thumbnail and marks late duplicates, deleting their objects. A duplicate owns no bytes, points at the canonical via `duplicateOfId`, is excluded from listings unless `status=Duplicate` is asked for by name, and is deleted along with its canonical — it can never be promoted. Map ↔ gallery cross-links ride URL/route params: `/locations?at=<lon>,<lat>` (mobile: the Map tab's `at`) flies to a photo, and `?from=&to=` day bounds (YMD, the map's own vocabulary) filter the gallery to a pin's day.
- **Contact relationships read the same from both contacts** — never branch UI on which contact stores one. `ContactDto.relations` is storage (the copies that contact holds), not the relationship: web renders `GET /contact-api/contacts/{id}/relations` and edits from either side; mobile uses `useContactRelations` (mirror `relationCopiesOf` → `@lupira/cal-domain/contactRelations` `resolveRelations`, the same merge as contact-api's `RelationResolver`). `label` is per side (the viewed contact's word for the other); since/note/ended are shared. The follow-up move to a `Relationship` aggregate is planned in LupiraContactApi `docs/relationships.md`.
- **Comms topics**: a contact's finished topics from LupiraCommsApi (`/comms-api` BFF prefix, `@lupira/cal-api/query/comms`, hook `useContactTopics`). Reached only from the contact detail's "Comms" link → `/contacts/:contactId/topics/:topicId?`, one `React.lazy` pane (`ContactTopicsPane`, default export) that lists topics or renders one topic's messages — nothing is fetched, and no comms code is loaded, until that link is clicked. comms has no topic↔participant link, so `contactId` narrows on `Topic.LastConversationId`: a topic answers for the conversation its latest message landed in. Ask for `status=Closed&status=Released` (`SETTLED_TOPIC_STATUSES`) — the closer moves topics on within a sweep, so filtering on `Closed` alone finds nothing. Labels are the opening message's first words until the titling pass runs (`titled: false` → `topicHeadline` quotes them).
- **Task deadlines**: third grid source from LupiraTasksApi (`/tasks-api` BFF prefix, hook `useTaskDeadlines` over the generated `useListItems`). Open non-Cancelled tasks with `dueAt` in range render as all-day chips — which tasks qualify, due-day pinning, overdue and the deep link are `@lupira/cal-domain/tasks`; `fromTask` (web) and `taskDeadlineRows` (mobile) only shape the row (`fromTask`; the deadline/overdue treatment is an sx branch in WeekGrid/MonthGrid, not a class); click → `?task=<listId>:<itemId>` TaskCard with `lupiratasks://task/<listId>/<itemId>` deep link + tasks.lupira.com list fallback; the `CalendarToggles` "Deadlines" toggle gates the fetch. Tasks-api dev listens on 8080 (Kestrel section beats ASPNETCORE_URLS).
- **/items page**: global list/search across all readable calendars in one infinite query (`useItemSearch`, skip/take paging, filters in URL params: q/tag/cal/category/status/range/from/to/parent); rows open the shared `?item=` drawer. Search covers accepted items only (never proposed). Hierarchy: one visual level — children nest under their parent's first loaded occurrence (`domain/itemTree.ts`; parent absent → flat row with `↳ parent` chip); `?parent=<id>` drills into all children (API defaults parentId searches to all-time); drawer has a HierarchyPanel (distinct from RelationsPanel's cross-API edges).
- **Mobile event editor** (`ItemEditScreen`): a new event starts on the last-used calendars (`prefs.lastCalendarIds`) with you invited as going — your contact id is `me.contactId` in `mirror_meta`, refreshed by each sync from `/contact-api/me`; an `item.invite` op's `accept` ids get an RSVP right after the invite. Events you're not on offer Join (detail) and Add me (`PeopleSheet`). The place sheet is one list ranked by `@lupira/cal-domain/placeRank` (saved, hotspots decayed by last visit, typeahead `Place`s only, contacts' addresses by name; invited people's homes lead), each row saying who lives there (`residents` — current addresses only). Title, when, place, description up front; the rare fields are More rows opening `ui/event/*Sheet` (`ui/components/Sheet`). One Save = one `saveItem` enqueue: core revise + `item.file`/`item.unfile` + `item.invite`/`item.uninvite` (participation has no section guard; each invite request carries a key derived from the op's command id + contact, and uninvite removes by contact — neither needs the participation id an offline invite doesn't have yet). Place = a geo `placeId` + label — cal-api 400s free-text `location` without one. Timed events carry `startTimezone` (the device's by default; the calendar bridge keeps an existing zone): the server repeats a zoned series on that zone's wall clock, so `@lupira/cal-domain/recurrence` does too — parity fixtures come from LupiraCalApi `tools/FixtureEmitter` (a UTC UNTIL bounds the instant; a floating or date one, the wall clock).
