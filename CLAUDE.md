# LupiraCal — agent notes

- BFF pattern: ~/Nextcloud/Familj/DevOps/Guides/bff-pattern.md
- Shared frontend conventions: ~/Nextcloud/Familj/DevOps/Guides/frontend-estate.md (repo-specific deviations below).
- **Purpose**: web + mobile UI over LupiraCalApi's REST surface (no sync-protocol paths on web). Visualizes the temporal backbone: calendar Class/Kind, ItemKind details, Prompt/Action payloads, completeness, availability segments, curation, tags, metadata, relations.
- **Workspaces**: `packages/domain` (`@lupira/cal-domain`, pure TS consumed as source, no deps, never imports generated DTO types), `packages/tokens` (`@lupira/cal-tokens`, same purity; consumers re-type records against generated enums as the drift tripwire), `packages/api` (`@lupira/cal-api`), `apps/web`, `apps/mobile` (Expo 57 "Lupira Calendar", package `com.lupira.calendar`, scheme `lupiracalendar`, Authentik client `lupira-cal-mobile`, own orval gen against the BFF prefixes).
- **BFF**: Authentik client `lupira-cal`, cookie `__Host-lupira-cal`. YARP → seven upstream roots (cal, contact, geo, tasks, location, photo, comms; prefix stripped, bearer attached). No anonymous surface. CalApi Development accepts the forwarded `X-Dev-User`.
- **`/depz`** (BFF's own, not proxied): non-gating availability report, one anonymous `readyz` probe per `ReverseProxy:Clusters` entry named by registry service (`Dependencies/DependencyTargets`); `X-Probe-Key` = `Depz:ProbeKey`, blank = off.
- **`exposed.json` exceptions** to "no catch-all": `exposed.static` (geo-api `/basemap`, GET-only file subtree; glyph ranges can't be enumerated) and `exposed.device` (location-api `/ingest/location*`, mounted at the upstream path, no transform, `AuthorizationPolicy: Anonymous`).
  - Ingest is Anonymous because only location-api holds the device keys: the BFF gates on `DeviceKey {32hex}.{64hex}` well-formedness (`Auth/DeviceKeyHeader`, 401 before the proxy so a device never gets an OIDC redirect) and the YARP transform stands aside. It stays out of the merged spec (the generated client only expresses Bearer), which is why the uploader is hand-written.
  - Unreachable: `/mcp`, `/internal/*`, `/dav-backend/*`, `/depz`, `/openapi/v1.json`, `/scalar`, `/pingz`, comms `/ingest`, tasks `/shared/{token}` and `/users/directory`.
- **Contract**: seven upstream specs merged (cluster tag per upstream). Kiota client so far: `Upstream/Contact` (`GET /api/contacts/{id}/context`). `TODO(kiota)`: `NullableRefNormalizer` and `normalized-specs.test.ts` go once a release carries [the oneOf-null fix](https://github.com/microsoft/kiota/pull/8064).
- **API client** (`packages/api`): `query/*` for reads straight off the server, `fetch/*` for callers that own their caching. Every `/me` is dropped but contact's (carries `contactId`); the BFF owns identity at `/auth/user`. Numerics generate as plain `number` (`NumberHandling.Strict`) — never re-add `Number()` coercion.
- **Layering**: `data → state → ui` (+ leaf `config/`) on web, `domain → data → sync → state → ui` on mobile, eslint-plugin-boundaries v7. `@lupira/cal-domain` holds grid math, occurrence column layout, recurrence prose, partial dates, task-deadline rules, basemap style handling, place-lookup batching, ranking, filters. Anything both apps show or decide — the event form (`itemForm`), calendar choice, wording (`photoFormat`, `participation`, `wording`), map/search constants — lives there, and shared visual values (`mapPaint`, scrims/emphasis/tones in `color`) in `@lupira/cal-tokens`; an app keeps only its adapters and widgets.
- **Shared vs per-app.** A hook's query key, gating and return shape stay per-app, and so do the MapLibre layer components (same expressions, per-renderer wrappers and touch-vs-pointer sizes). What remains in `useMapData` / `usePhotoLibrary` after delegating to `mapFeatures` / `photoFormat` is DTO-vs-mirror-row adaptation, not drift. `@lupira/cal-tokens/mapLayers` is the one layer list.
- **Mobile keeps hand-written hooks over the generated *fetchers* — do not swap in the generated *hooks*.** Mobile's query keys are the sync engine's invalidation contract: `sync/reactivity.ts` invalidates by domain aggregate (`['photos']`, `['contacts']`, `['items']`, `['occurrences', monthKey]`), react-query matches by prefix, and every hook nests under its aggregate, including cross-API ones (`['photos','event-links']` is a cal-api relations call filed under photos). Route-keyed hooks would silently stop matching. The mobile `QueryClient` defaults to `staleTime: Infinity, retry: false` for the local mirror; generated hooks would fetch once, forever. The web has no sync engine, which is why generated hooks fit there.
