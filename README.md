# LupiraCal

Web frontend for [LupiraCalApi](https://github.com/danbro96/LupiraCalApi), consuming its REST surface only. Its purpose is visualizing the temporal-backbone data generic calendar clients can't see: calendar classes and kinds, typed item details, event-bound LLM prompt/action payloads, completeness scores, availability segments, inbox curation, tags, metadata, and cross-API relations.

## Shape

An npm-workspaces monorepo; one Docker image holding the web app:

- **`src/LupiraCalBff`** — a .NET 10 BFF. Drives Authentik OIDC (Authorization Code + PKCE, `lupira-cal` client), keeps tokens server-side in an HttpOnly cookie session (`__Host-lupira-cal`), and proxies `/api/*` → LupiraCalApi via YARP with the user's bearer attached. The SPA never holds a token; there is no CORS.
- **`apps/web`** — a Vite + React 19 SPA served from the BFF's `wwwroot`. Online-only (React Query, the server is the source of truth). The API client and react-query hooks are **generated by orval** from the BFF's own build-time OpenAPI doc (`openapi/LupiraCalBff.json`, refreshed via `npm run gen:api`).
- **`packages/domain`** — `@lupira/cal-domain`, shared pure-TS calendar/contact logic (grid math, occurrence layout, recurrence prose, partial dates), consumed as source. No dependencies; its eslint config enforces purity.
- **`apps/mobile`** — "Lupira Calendar" Android app (Expo dev client): offline-first SQLite mirror of the cal + contact APIs with a transactional outbox, native OIDC, hand-rolled grids, and OS bridges (Android account with calendar/contacts sync adapters, two-way). Program history in `docs/mobile/milestones.md`; releasing in `docs/mobile/release.md` (EAS → Play internal testing).

SPA layering, enforced by `eslint-plugin-boundaries` (downward-only): `data → state → ui` plus a leaf `config`; `@lupira/cal-domain` is importable from every layer.

## Screens

- **Calendar** (`/`) — hand-rolled month/week/day grids. Occurrences arrive recurrence-expanded from `GET /items?from&to`, one query per visible calendar (colors/filters per source calendar). Availability-kind calendars render as a background band; proposed items ghost dashed; System calendars toggle in the sidebar.
- **Item drawer** (`?item=<id>` on any route) — every REST-exposed field: times/RRULE, place (with map link), tags, typed kind details, ⚡ prompt/action payload editor (XOR, 409-aware), completeness ring + gaps, attendees with RSVP actions, calendar memberships + curation, relations, metadata merge editor.
- **Inbox** (`/inbox`) — the curation queue: items proposed into any calendar, accept/reject per membership.
- **Contacts** (`/contacts`) — search, reach fields (emails/phones/addresses/profiles), birthdays, groups & organizations, completeness.
- **Map** (`/locations`, lazy chunk) — MapLibre over geo-api's self-hosted basemap (`/geo-api/basemap/*`): event pins colored per calendar (click → item drawer), GPS movement from location-api (dwell-sized visit circles, activity-colored track lines, live position), contact-address pins (household-deduped, labeled "names · kind", on by default; a History chip adds former residencies as hollow faded pins with their fuzzy period), saved places. A ☰ List panel indexes everything on the map by kind for click-to-fly navigation. Time range + layer toggles ride URL params; `?place=<id>` opens the place panel (containment, items here, contacts here) and search covers the gazetteer with a nominatim fallback.
- **Manage** (`/calendars`) — containers with class/kind/color/timezone/access, creation, and owner sharing by email.

## Develop

```bash
# API (sibling repo; Development accepts X-Dev-User)
cd ../LupiraCalApi && dotnet run --project src/LupiraCalApi     # http://localhost:5255

# BFF (dev auto-auth, forwards X-Dev-User, proxies /api → :5255)
dotnet run --project src/LupiraCalBff                            # http://localhost:5181

# SPA (proxies /api + /auth to the BFF) — run from the repo root
npm install && npm run dev                                       # http://localhost:5174
```

Root scripts fan out over the workspaces (`lint`/`typecheck`/`test`) or delegate to the client (`dev`/`build`/`preview`/`gen:api`):

| Script | Does |
| --- | --- |
| `npm run dev` / `build` / `preview` | Vite |
| `npm run lint` / `test` / `typecheck` | eslint / vitest / tsc, every workspace |
| `npm run gen:api` | build the BFF to re-emit `openapi/LupiraCalBff.json`, then regenerate routes + the orval client |

## Deploy

`docker build -t danbro96/lupira-cal-web .` (repo root). Runs at `https://cal.lupira.com` behind cloudflared; compose in `deploy/` (port 40881, API at 40880). Authentik: add redirect URI `https://cal.lupira.com/signin-oidc` to the `lupira-cal` client. Data-protection keys persist in the `cal-web-keys` volume so sessions survive restarts.
